# 技术设计：全局通关分享卡片

## 技术方案
- Everest Level.OnComplete 在草莓结算后冻结本次 Session 数据。
- 最近记录保存到 Mod SaveData；SL 跟踪独立于回滚快照，并接入 SpeedrunTool 存读档回调。
- 普通草莓按地图实体 ID 统计，全收集检查地图实际存在的草莓、磁带和爱心；金草莓按已收集实体判断。
- 卡片为 ChatItem 子类，提供高度测量和渲染；聊天列表按实际高度计算滚动。

## 架构决策 ADR
### ADR-001：独立结构化消息
采用专用发送包和广播包，在注册表末尾追加。拒绝将 JSON 混入普通文本：普通消息有 64 字符限制，也无法可靠区分用户输入和卡片。
发送者 ID 和发送时间由服务端填入，广播范围固定为全局。

## 视觉设计
深紫半透明底、粉色细边框和左侧强调线。第一行玩家和通关标题，第二行地图及 A/B/C 面，第三行突出时间及死亡次数，末行三个文字徽章。
金草莓成功时使用金色强调；SL 使用琥珀色。长地图名按实际宽度截断。

## 安全与性能
限制 SID/名称长度、枚举、非负计数和合理用时，拒绝控制字符；每连接限制分享频率。不改变普通聊天长度限制。
卡片保存已冻结数据，渲染不进行网络或文件操作。

## 测试与部署
验证数据往返、非法输入、节流、SL 生命周期和时长格式。构建服务端及使用本机游戏引用构建客户端，不自动启动或部署。
客户端与服务端同步升级；游戏内手工验收普通通关、金草莓、SL、换图分享、长名称和聊天滚动。
